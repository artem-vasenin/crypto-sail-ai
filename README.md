# Crypto Sail AI v0.1.1 — исследовательский бот на Go с локальной Qwen

**Новый независимый проект.** Bybit V5 USDT Perpetual (`linear`), Go **1.23.2**, SQLite, Ubuntu, Qwen3-8B через локальный `llama-server`. **В этой версии физически нет кода для отправки биржевых ордеров.**

Проект создаётся для проверки цепочки: `данные → признаки → гипотезы → анализ → WAIT/REJECT/READY → виртуальное исследование → статистика`. Это **первая работающая исследовательская основа**, не завершённый торговый робот и не доказанная прибыльная стратегия.

## 1. Что действительно реализовано

- Публичный Bybit REST-клиент: постраничный список `Trading/LinearPerpetual/USDT`, тикеры, kline; проверка ответов, 429/5xx retry, сортировка, фильтр незакрытых свечей, валидация.
- Surface-анализ рынка: исходные turnover, spread, bid/ask, OI/funding, возраст инструментов; статусы `CANDIDATE/WATCH/REJECT`, конкретные причины, **без потолка номинальной цены**.
- Deep-признаки на `5/15/30/60/240`: SMA, EMA, RSI14, ATR14, ATR%, swing pivots и HH/HL/LH/LL/EQ/UNKNOWN. **Нет пока** EMA200, MACD, 1d/1w, кластеров уровней и полноценного BTC-context. SMA200 честно будет `insufficient_history` при 100 свечах.
- Qwen3-8B: прямой OpenAI-compatible Chat Completions `localhost:8080`, JSON Schema, `snapshot_id`, отклонение invalid/truncated/несовпадающих ответов, триаж/Deep. Роль только исследовательская.
- Файловая SQLite с WAL, миграцией, foreign keys, журналами решений и виртуальных событий, `integrity_check`, безопасной онлайн-резервной копией.
- WAIT-сущность и проверка таймера/entry zone, **без автозапуска новой Deep**.
- Офлайн-симуляция уже исполненной виртуальной позиции: entry, TP/SL, комиссии, гипотетическое проскальзывание, первоначальный `R`, cost-aware BE, ATR trailing, worst-first OHLC и gap. Отдельная консервативная модель виртуальной PostOnly-заявки с частичным исполнением по trade-through.
- Шесть синтетических кейсов для проверки Qwen (`benchmark`).

**Ещё НЕ реализовано:** непрерывный 24/7 автопайплайн, scheduler/переоценка WAIT, WebSocket/реальные trade prints, полная история свечей, восстановление активно ведущейся непрерывной бумажной позиции, полной последовательности виртуальных limit/partial fills → position в реальном времени, полноценный post-exit worker, статистический анализ доходности, grid, реальная торговля. См. `docs/ROADMAP.md`.

## 2. Установка на Ubuntu 24.04

В каталоге распакованного проекта:

```bash
sudo apt update
sudo apt install -y golang-go build-essential libsqlite3-dev make
GOTOOLCHAIN=local go version      # поддерживается Go >= 1.23.2; протестировано также на 1.27.x
GOTOOLCHAIN=local CGO_ENABLED=1 go test ./...
make check                        # тесты, race detector, vet и сборка
./bin/sail doctor
```

**Внимание:** пакет `golang-go` из репозитория Ubuntu не обязан установить именно 1.23.2. Если `go version` показывает другое — использовать установленный Go 1.23.2 из своего PATH; не предполагать, что `apt` обеспечит нужную версию. Никакой Go-исходник не требует сторонних Go-модулей, но системная SQLite и C-компилятор необходимы. `CGO_ENABLED=0` **не поддерживается**.

**Проверка:** первоначальная сборка прошла на Go 1.23.2; пользователь успешно выполнил `make check`, офлайн-проверки, Bybit Surface и реальный Qwen benchmark на Go 1.27.x. Исправление triage v0.1.1 проверяется отдельно на фактическом `llama-server` после распаковки. Сам номер версии Go не является оценкой безопасности торговой стратегии.

## 3. Команды: безопасное начало

В корне проекта:

```bash
make build
./bin/sail help
./bin/sail doctor
./bin/sail db-check
./bin/sail paper -file testdata/paper-example.json
./bin/sail status
./bin/sail backup -out data/backup-001.db
```

`paper` не подключается к Bybit и не вызывает Qwen. Он использует **синтетические** OHLC-свечи, принимает entry как ранее исполненный и выводит условный результат. Повторные запуски добавляют новые виртуальные записи, не перезаписывая предыдущие.

### Получить публичные котировки Bybit (требуется доступ к API Bybit)

```bash
./bin/sail collect -symbol BTCUSDT -tf 60 -limit 100
./bin/sail surface -show 10
./bin/sail status
```

`collect` сохраняет в БД только закрытые свечи (отсортированы от старых к новым). `surface` собирает **полный доступный постраничный** список USDT perpetual и все тикеры, сохраняет исходные значения и причины. Нет ордеров и приватных API-ключей.

### Ручной анализ локальной Qwen

Сначала проверьте, что установленный на Ubuntu `llama-server.service` обслуживает `/v1/models`:

```bash
curl -sS http://127.0.0.1:8080/v1/models
./bin/sail triage -limit 5
./bin/sail deep -symbol BTCUSDT -side LONG -ai
./bin/sail watch-check
```

`triage` требует свежего `surface`. На выходе `REQUEST_DEEP_ANALYSIS`, `WATCH`, `REJECT` — исследовательские рекомендации; **пока нужно вручную запустить** `deep` для нужного символа. Команда `deep` собирает пять таймфреймов и передаёт ограниченные вычисленные признаки Qwen. Можно выполнить `deep` **без `-ai`** и проверить чистые признаки Go:

```bash
./bin/sail deep -symbol BTCUSDT -side SHORT
```

`watch-check` читает сохранённые WAIT и свежие тикеры. `trigger=true` означает «пришло время новой глубокой проверки» — не приказ войти. Текущая команда только показывает триггеры, не планирует фоновое выполнение и не открывает позицию.

### Проверить качество Qwen на синтетике

```bash
./bin/sail benchmark -file testdata/llm-benchmark.json -limit 6
```

Сохраняет метаданные и сырой ответ в SQLite. Сравнивает решения с **иллюстративными допустимыми классами**, не с доходностью. Частота совпадений — **не вероятность успешной торговли**.

## 4. Где лежит SQLite

По умолчанию `data/crypto-sail.db`. БД создаётся автоматически в файловой системе. Для переноса/бэкапа используйте команду `backup`, а не простое копирование основного файла при работающем WAL. Файлы `data/` исключены из Git и итогового ZIP. См. `docs/STORAGE.md`.

Чтобы не трогать рабочую базу при эксперименте:

```bash
./bin/sail paper -db data/experiment.db -file testdata/paper-example.json
./bin/sail status -db data/experiment.db
```

## 5. Безопасность и ограничения

- `paper_only=true` — обязательный конфигурационный инвариант. В коде **нет** приватного REST-клиента или WebSocket для исполнения.
- `llm_url` только `http://127.0.0.1:8080`, модель не получает `tools` и не ходит в интернет; `llm-agent:8090` не нужен.
- Наличие SQLite и технически правильного JSON **не** означает успешную торговую аналитику.
- **Точность офлайн OHLC-сделок ограничена:** в одном баре SL имеет приоритет перед TP, maker-order fill определяется лишь отдельным допущением; финансирование и fee-tier выставлены примерами, не извлекаются с вашего аккаунта.
- В `paper-example.json` цены не являются настоящими BTC котировками. Не вводить их в реальную торговлю.

## 7. Обновление v0.1.1 и включение Git

Присланный пользователем проект исправлен без повторного применения повреждённого `.patch`: `triage` теперь требует непустые `reason_codes` в JSON Schema, пишет точную причину ошибки и сохраняет отклонённый сырой ответ для аудита. Добавлены регрессионные тесты. **Реальная Qwen после этого исправления ещё требует проверки на Ubuntu.**
