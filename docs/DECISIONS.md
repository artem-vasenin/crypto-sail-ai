# Архитектурные решения (ADR)

## ADR-001 · Первый независимый релиз 0.1.0

**Решение:** отдельный Go-модуль; старая ветка v0.2.x не импортируется. **Причина:** массивный legacy execution, OAuth, смешение grid/long/short и отсутствие AI before soft filters. **Цена:** потребуется поэтапно заново реализовать все более сложные модули, не считать старые исправления автоматически перенесёнными.

## ADR-002 · Go 1.23.2

**Решение:** фиксируем `go 1.23.2` и `GOTOOLCHAIN=local`, поскольку эта версия доступна для непосредственной проверки здесь. **Риск:** Go 1.23 не получает security fixes в ноябре 2026. **Gate:** до любого live — миграция на поддерживаемый Go и повторный аудит.

## ADR-003 · SQLite через libsqlite3 (CGO)

**Решение:** файловая SQLite с WAL, foreign keys, online-backup, без скачиваемого Go-драйвера. **Причина:** из среды создания недоступен Go package proxy, системная SQLite реально имеется и код здесь компилируется. **Цена:** требуется gcc/clang + `libsqlite3-dev`, `CGO_ENABLED=1`; это сознательный инфраструктурный компромисс. При росте масштаба оценить PostgreSQL/TimescaleDB, не заменять сейчас излишне.

## ADR-004 · Qwen напрямую без llm-agent

**Решение:** `POST http://127.0.0.1:8080/v1/chat/completions`, без 8090/ChatGPT/Keychain/tools. **Причина:** агент для программирования добавляет свои web-инструменты и системный промпт, не нужен для структурированной торговой оценки.

## ADR-005 · LLM до мягких фильтров, после data quality

**Решение:** Surface WATCH может попасть в Qwen наравне с CANDIDATE; REJECT повреждённых данных не может. **Причина:** старый `trend_quality` массово отсекал рынок до ИИ. **Риск:** GPU ограничен; нужны batch/очередь/cooldown и независимая выборка отказов.

## ADR-006 · Сначала воспроизводимые данные, потом автономность

**Решение:** текущий CLI делает независимые шаги; сначала проверяем контракт каждого шага тестами, после интегрируем scheduler. **Цена:** пока нет непрерывного готового бота; это явно отражено в README.

## ADR-007 · PAPER не равен preview

**Решение:** баровая модель хранит неизменный R, моделирует комиссии, проскальзывание, BE/trailing; одновременно задетые SL+TP трактуются неблагоприятно. **Ограничения:** из баров нельзя доказать реальные fills; вход условно заполнен. Отдельный PostOnly simulator требует последующей trade-through агрессии, но его оценка участия 10% тоже допущение.

## ADR-008 · Без real execution даже за флагом

**Решение:** никаких приватных Bybit методов и торговых ключей в коде. `paper_only=false` — ошибка конфигурации, а не переключение. **Причина:** исследовательская безопасность и недоказанная статистика.

## ADR-009 · ИИ может ошибаться даже в валидном JSON

**Решение:** проверять полный ответ (`finish_reason=stop`), DTO, эхо snapshot/symbol, лимиты и Go gates. **Цена:** некоторые разумные ответы могут быть отвергнуты; это лучше скрытого допуска невалидной сделки. Следующий шаг — проверка grounded evidence, версий промптов и статистических ошибок.
