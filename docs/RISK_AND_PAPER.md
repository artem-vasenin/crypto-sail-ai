# Виртуальные позиции: SL, TP, комиссии, проскальзывание, безубыток и trailing

## 1. Смысл модуля

`internal/observer` — отдельный тестируемый **офлайн вычислитель**. Никаких ордеров Bybit, ключей, реального баланса, плеча или механизма ликвидации в нём нет. На текущем этапе есть две **не связанные автоматически** модели:

1. `EntryOrder`: условная PostOnly-заявка, которая может оставаться `PENDING`, частично исполняться `PARTIALLY_FILLED`, быть `FILLED`, `EXPIRED` или `CANCELLED`. Вход не считается filled просто потому, что цена коснулась лимита.
2. `Position`: уже виртуально исполненная позиция, которая сопровождается по массиву закрытых OHLC. Команда `sail paper` создаёт **сразу Position**, без моделирования реального пути лимитной заявки.

Это предохранитель от неправильного обещания «сделка обязательно исполнилась». Для реального Paper Observer эти две модели ещё нужно объединить через публичные сделки, bid/ask и отдельный контроллер.

## 2. Первоначальный риск и R

Для LONG/SHORT: `initial_risk_price = abs(entry − initial_SL)`, `initial_risk_usdt = initial_risk_price × quantity`. После заполнения записи эти величины не изменяются при переносах SL.

Вычисления:

- `gross PnL LONG = (exit − entry) × qty`;
- `gross PnL SHORT = (entry − exit) × qty`;
- `net PnL = gross после условного exit-slippage − entry_fee − exit_fee − funding_cost`;
- `net R = net PnL / initial_risk_usdt`.

Это **price-risk R**, не риск ликвидации и не нормализация по используемой марже. Плечо нельзя трактовать как усилитель качества сигнала.

## 3. Постановка SL/TP до входа

`NewFilled` отклоняет отсутствующие/нечисловые/нулевые цены, SL на неправильной стороне, TP на неправильной стороне, нулевой размер, некорректные параметры расходов. При заданном `MinNetTargetR` вычисляется **прогнозируемая net-цель** с комиссиями и заданным exit-slippage. Недостаточная чистая цель приводит к ошибке, а не к фантазии о доходности.

Важно: это **не** полный portfolio risk gate. Пока не сделаны `minNotional`, размер по qtyStep, рыночная глубина, margin mode, funding schedule, portfolio exposure и liquidation buffers. Нельзя считать `NewFilled` достаточной защитой для реального ордера.

## 4. Безубыток с учётом издержек

Рассмотрим цену `E`, сумму затрат на вход на единицу количества `E × fi`, ожидаемую ставку комиссии выхода `fo`, запас проскальзывания на выходе `s`, и funding cost на единицу количества `F/Q`.

Для **LONG** цена trigger/SL, при которой ожидаемый net PnL ≥ 0:

```text
BE_long = [E × (1 + fi) + F/Q] / [(1 - s) × (1 - fo)]
```

Цена затем округляется **вверх** к tick size. Для **SHORT**:

```text
BE_short = [E × (1 - fi) - F/Q] / [(1 + s) × (1 + fo)]
```

Цена округляется **вниз** к tick size.

Стоп переносится только когда Close завершённой свечи дал ≥ `BETriggerR` от **исходного** риска, и только если новая цена стопа остаётся по защитную сторону текущего Close. Этот алгоритм консервативен, но **не гарантирует безубытка на гэпе и в реальном стакане**. Стоимость финансирования в текущих default rules равна 0: для реальной статистики funding нужно измерять отдельно, а не считать его бесплатным.

## 5. Trailing SL

В прототипе при `TrailTriggerR`:

```text
LONG:  new_SL = floor_to_tick(Close − ATRMultiplier × ATR)
SHORT: new_SL = ceil_to_tick(Close + ATRMultiplier × ATR)
```

Для LONG `new_SL > current_SL`, для SHORT `new_SL < current_SL`, иначе событие не происходит. Проверка выполняется только после закрытия текущего бара; новый SL действует **со следующего бара**, что предотвращает использование будущей внутрибара информации задним числом.

Стандартные значения **исследовательские, не оптимальные**: BE после +1R, trailing с +1.5R, ATR multiplier 2.5. Сравнивать альтернативы после накопления достаточных samples, включая `GOOD_DIRECTION_BAD_ENTRY`, ранний SL, случаи пост-выходного продолжения и потери после комиссии.

## 6. Неоднозначные свечи и гэпы

Если OHLC бара одновременно касается SL и TP, функция выбирает **SL прежде TP**; фиксирует `AMBIGUOUS_BAR`. Если open нового бара проскочил через SL невыгодно, exit моделируется по худшему `open` (плюс задаваемый slippage buffer), а не по гарантированному стоп-уровню. Это снижает оптимизм бэктеста, но всё равно не является симуляцией полноценной торговой книги.

`MFE` и `MAE` по текущей реализации используются в **ценовых единицах**, а `MaxFavorableR` относительно initial-risk price. MFE/MAE, рассчитанные по свечным high/low, не доказывают исполнение по ним. Время-to-0.5R/1R пока не измеряется — будущий этап.

## 7. Виртуальный PostOnly

- Для LONG лимит на стороне bid или ниже; для SHORT — ask или выше (после выравнивания по tick size).
- Сделка **не** исполняется при одном касании уровня или по агрессору неправильного направления.
- Для предположения о fill требуется последующая агрессивная сделка **сквозь** лимит как минимум на один tick; используется условное участие не более 10% объёма этого trade print.
- Возможны частичные исполнения и timeout; нет допущения fill по факту `order/create`.

Это всё равно **приближённая оценка**, поскольку очередь заявок, доля исполнений и latency неизвестны. Брать её как реальный fill или реальный maker fee запрещено.
