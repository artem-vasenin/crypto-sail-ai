# Безопасное обновление Crypto Sail AI и первое включение Git (Ubuntu)

## Суть исправления

Новый ZIP построен из присланного 16.11.2026 пользовательского `arch.zip`, а не наложен на неизвестную версию через patch. Он содержит **исходники и документацию**, но не содержит `data/crypto-sail.db`, `data/*.db-wal`, `data/*.db-shm`, готового `bin/sail`, ключей или `.git`.

Отдельная существующая база — важнейший актив исследовательского проекта: ничего из `data/` не удалять и не распаковывать туда старую копию. Даже если вы ранее частично применили патч, новый архив содержит ПОЛНЫЕ исправленные исходники и заменит одноимённые Go-файлы. Не запускайте старый `.patch` снова.

## 1. Резервная копия и обновление

Из существующего каталога `~/work/my/go/Crypto-Sail-AI`:

```bash
cd ~/work/my/go/Crypto-Sail-AI
./bin/sail backup -out data/backup-before-triage-fix.db
./bin/sail db-check
```

Убедитесь, что `backup` прошёл успешно. Это **онлайн-резервная копия SQLite**; копирование одного `.db` при активном WAL недостаточно. Сохраните и исходный `arch.zip` отдельно на случай ручного восстановления. Не удаляйте ничего из `/data/`.

Скачайте исправленный ZIP **вне** папки проекта, например в `~/Downloads/`. Затем распакуйте поверх исходников:

```bash
unzip -o ~/Downloads/Crypto-Sail-AI-v0.1.1-triage-fix.zip -d ~/work/my/go/Crypto-Sail-AI
```

**Важно:** в ZIP файлы лежат сразу в корне (`go.mod`, `cmd/`, `internal/`, `docs/`), без вложенного каталога. `unzip -o` перезаписывает одноимённые исходники, но не удаляет файлы, которых нет в архиве. Включённые в ZIP файлы не содержат БД и бинарника, поэтому они не затронуты. Любые свои несохранённые изменения в этих исходниках перед распаковкой сохраните отдельно.

## 2. Тестирование новой версии

```bash
cd ~/work/my/go/Crypto-Sail-AI
GOTOOLCHAIN=local CGO_ENABLED=1 go test -count=1 ./...
make check
bash scripts/verify_offline.sh
./bin/sail db-check
```

`make check` пересобирает `bin/sail`. Для интеграции с настоящей Qwen после этого запускайте последовательно:

```bash
./bin/sail surface -show 5
./bin/sail triage -limit 5
```

Surface-снимки должны быть свежими. Даже если новый ответ Qwen некорректен, будет диагностическая ошибка и запись в `llm_calls`, но решение не должно появляться в `decisions`. **Нельзя считать успешный JSON или статусы triage торговым сигналом.**

## 3. Создание первого локального Git-репозитория

После проверки и непосредственно **в корне проекта**:

```bash
cd ~/work/my/go/Crypto-Sail-AI
git init -b main
git status --short
git add .
git status --short
git diff --cached --name-only
```

**Проверьте список перед первым коммитом.** В нём должны быть Go-файлы, `AGENTS.md`, `Makefile`, `.gitignore`, документация, конфиг-пример, testdata и скрипты. **Не должно быть** `data/`, `bin/`, `*.db`, `*.db-wal`, `*.db-shm`, `*.zip`, `*.patch`, секретов или `.env`.

Если Git попросил настроить автора (это настройки только вашего локального Git, а не проекта):

```bash
git config user.name "Ваше имя"
git config user.email "your-email@example.com"
```

Только после проверки `git diff --cached --name-only`:

```bash
git commit -m "Initial research baseline: v0.1.1 triage fix"
git status
```

Команды **не отправляют код на GitHub/GitLab**, не создают remote и не публикуют базу. Для будущих правок работайте через отдельные коммиты:

```bash
git status
git diff
git add <конкретный-файл>
git commit -m "Describe tested change"
```

**Не** применяйте `git reset --hard`, `git clean -fdx`, `rm -rf data` без понимания последствий — так можно потерять локальные изменения и данные.

## 4. Если `git init` пишет, что репозиторий уже существует

Не запускайте повторную инициализацию с перезаписью истории. Сначала проверьте `git status` и `git log -3 --oneline`. Сверьте файлы и выберите обычный коммит. Не добавляйте `.git` из архивов третьих лиц.

## 5. Проверка отсутствия случайной публикации базы

`git status --ignored --short data bin` покажет игнорируемые файлы с `!!`. Это ожидаемо. `.gitignore` предохраняет при `git add .`, но не скрывает файлы, ранее принудительно добавленные в индекс; проверять `git diff --cached --name-only` перед коммитом всё равно необходимо.
